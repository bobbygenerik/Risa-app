## 2026-06-26 - Prevent Intermediate String Allocations via Independent Keyword Checking
**Learning:** In hot paths analyzing many objects sequentially (like  running over large EPGs), constructing new compound strings purely to pass to a combined matching method (e.g., `'$title $category $description'`) generates heavy memory pressure due to repeated allocation. String concatenation allocates entirely new objects in memory that the GC must immediately clean up if they are just temporary test inputs.
**Action:** When searching for keywords across multiple separate fields, avoid concatenating those fields first. Instead, pass the fields individually to the matcher and chain the results using short-circuiting logical operators (`||`). This not only avoids the string allocation entirely, but the short-circuit evaluation skips subsequent checks entirely if an early match is found.
